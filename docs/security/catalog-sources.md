# Catalog sources: threat model

What a catalog source can do to the control plane and to what's installed, and what stops it. The design is in [ADR 0055](../adr/0055-catalogs-from-a-git-url.md); in [ADR 0077](../adr/0077-dockwells-catalog-in-its-own-repository.md), which lets a source follow a branch and hold images; for another store's catalog, which the control plane converts as it reads it, in [ADR 0078](../adr/0078-other-stores-read-on-the-server.md); and for a store's own logos and words, and SVG icons, in [ADR 0083](../adr/0083-a-stores-own-logos-and-words-and-stores-one-click-away.md). The code is in `internal/gitfetch`, `internal/netguard`, `internal/catalog/folder`, `internal/catalog/svgclean`, `internal/catalog/convert` and `internal/control/catalogapi`.

## What there is to protect

| Asset | Where it lives | Why it matters |
| --- | --- | --- |
| The control plane's disk and memory | The server it runs on, as root | A source is read when a plan is made, before anyone applies anything |
| What the control plane can reach on its network | This server, its private networks and its cloud's metadata service | A request it makes for a source could reach what no person can |
| What an install runs | Its project's pin, and the catalog it upgrades from | An upgrade runs whatever image the entry it comes from names |
| The panel, in a person's browser | The control plane's origin, with a signed-in session | A source's image is served from that origin, so a file a browser ran there could act as the person |

## Trust boundaries

- **A source's repository, and the host that serves it,** are a stranger's, whoever named them. Everything it sends is checked as if it means harm: its pack, its trees' names, its entries and its words.
- **An admin** can add, move or remove a source. Adding one reads the network and the disk when the plan is made, outside the revision store, and decides what anyone can install, so `SetCatalogSource` and `RemoveCatalogSource` need an admin's role on the install, checked before anything is read (ADR 0049). The revision engine holds the resource to an admin too, as it belongs to no project. Anyone with a role can list the sources. `ListCatalogSourceRefs`, which a form uses to check a repository as it's typed and to offer its branches, is an admin's too: it reads the network for whoever asks, through the same guarded client, with the same refusals, and answers with names and commit IDs alone.
- **Whoever applies the plan** chooses to trust the source's entries, as anything they add is theirs. A source's entry is never *tested*, as ADR 0029 says of the reviewed list.
- **A source that follows a branch** is trusted further: its repository's owner can change what the install offers, by pushing, with no person on the install. Adding it, or having it follow, is that trust, and its plan says so. Dockwell's own source follows Dockwell/catalog, whose main moves only by reviewed pull requests that pass the check a server makes.

## Threats and mitigations

| Threat | Mitigation |
| --- | --- |
| A tree names an entry `../../root/.ssh/authorized_keys`, and it's written there as root | gitfetch refuses a tree with an entry named empty, `.`, `..`, `.git` in any case, with a slash, a backslash or NUL in it, or twice, as Git does. Only `<id>.yaml` is read on or kept, written through `os.Root`, in a folder of each read's own. |
| A pack of a few hundred bytes stands for gigabytes: a delta that copies its base thousands of times, a chain made again for each delta on it, or a zlib bomb | The pack is kept on disk, 64 MiB at most, and indexed in one pass that only hashes what it inflates. Only the commit, the trees on the path and the folder's blobs are made of their deltas, each 8 MiB at most, what's made is kept within 32 MiB, and everything inflated or made counts against one budget of four times the pack's limit. The read stops with its context, a minute at most. |
| A pack of millions of tiny or empty objects, a few hundred KiB gzipped, costs the index gigabytes | A pack holds 100,000 objects at most, by its header's count, refused before anything is read. Each costs 1 KiB against the budget, whatever it holds, and the index keeps 64 bytes of it, in one slice: the most a pack may hold indexes in under 8 MiB. |
| Deltas that name their bases by name, each after the one it's made from, take a pass over the pack for each | A delta names its base by its offset, before it. A fetch asks for ofs-delta and no thin pack, so a delta that names its base by name never comes from an honest host, and is refused. |
| Many reads at once add up | The control plane fetches one source's commit at a time, and reads of one commit at once share its fetch. |
| Many lists at once, after a start or a move, each start a check of a store's apps, which overflows the reader of Compose files, and a check that says most apps are "waiting" is kept for everyone | Reads of the same commit and IDs before it share one check, as they share its fetch, and the check is every reader's, so one that leaves doesn't cut it short, within three minutes of its own. A check cut short, or one where any entry's Compose file wasn't read as the reader was busy, is kept for nobody, and the next read checks again. |
| A source's URL, or what its name resolves to, leads to loopback, a private network or a metadata service | It's read through `internal/netguard`, the one guarded client for addresses people name (#341): the address is checked when the plan is made and again as each connection is made, with no proxy from the environment. HTTPS alone. |
| A redirect leads elsewhere | None is followed, whatever the client: a host that moved says so in its answer, which names its status alone. |
| A host's words reach a person: an `ERR` line telling them to run a command | No error repeats what a host sent. Each names the host and a status, or says what was wrong with what it sent. |
| A host serves a commit other than the one named, or objects that aren't what their names say | Every object is named by its SHA-1, with the collision detection Git's own SHA-1DC has, from the commit down, and the pack's checksum is checked. A repository that names its objects by SHA-256 is refused, saying so. |
| A commit a fork made is served through the repository it was forked from, as GitHub does | The plan says which branch or tag of the repository the commit is, or that none is now, and that it may be a fork's. |
| An entry names the logo and screenshots Dockwell ships for one of its own apps, to pass for it | An entry's artwork is a file of the panel's, never a URL, so browsing asks nothing of another host. A source's entry is shown without any: the catalog drops its icon and screenshots, and the panel says which catalog it comes from on its card, its page and its install form. Its links open only as HTTPS addresses with no sign-in details. |
| An entry runs an image that moves | Each service's image, as an install reads the file, must name its digest. A check of lines alone missed a flow mapping and a quoted key. |
| A source added later, or one left when another goes, upgrades an install to a stranger's image | An install's pin records the catalog it came from, as the control plane knows it, never as the entry says. It upgrades only from there, and a source's plan names each ID that changes hands and each install that loses or regains its upgrades. |
| A source is added by a plain edit, with no read and no notes | A `catalog.source` changes only through `SetCatalogSource` and `RemoveCatalogSource`. |
| Plans fill the disk | A commit read for a plan is kept apart, the newest four, and kept for good only once a source applied names it. One no source names is removed. A commit's files are 16 MiB at most, 2,000 of them, 1 MiB each. |
| A host that's down makes every view of the catalog wait | A source that couldn't be read is taken as unread for five minutes, and the catalog shows the rest. |
| An image is a page or a script: HTML named `logo.png`, opened from the control plane's origin | Only `.webp`, `.png`, `.jpg`, `.jpeg` and `.svg` names are read at all. A raster image is checked by its first bytes, when it's read and again each time it's served, and its extension must say the same. It's served with the type its bytes say, `X-Content-Type-Options: nosniff`, and `Content-Security-Policy: default-src 'none'; sandbox`, so a browser that opens it on its own runs nothing. |
| An SVG image runs a script, with a `<script>`, an event handler, a `javascript:` link, animation that sets one, or foreign HTML | An SVG image is an icon alone, never a screenshot. It's kept and served only as `svgclean` writes it anew from an allowlist of elements and attributes that draw, each value checked; everything else is left out with what it holds. Cleaning is checked again each time it's served. A fuzz test holds what it writes to XML from the allowlist alone, the same when cleaned again. |
| An SVG image loads another file: an `<image>` or `<use>` of another host's file, a style sheet's `@import`, `url()`, `image-set()` or an escape that spells one, an `xml-stylesheet` instruction, or a font | An `href` names an element of the image, or a PNG, JPEG or WebP image written into the file whose bytes say so. A `url()` names an element of the image. A style sheet with an at-rule other than `@media`, an escape, or a function that loads a file refuses the image. Processing instructions go. Drawn as an `<img>`, a browser loads nothing an SVG image names anyway, and the image is served with `default-src 'none'; style-src 'unsafe-inline'; img-src data:`. |
| An SVG image opened on its own, from the control plane's origin, acts as the person | It's served with `Content-Disposition: attachment`, so opening it is a download, and with `sandbox` in its policy, so a browser that showed it would make it a page of no origin that runs no script. `Cross-Origin-Resource-Policy: same-origin` keeps another site from embedding it. |
| An SVG image stands for millions of drawings, by entities, uses of uses, masks of masks, clip paths of clip paths, markers at every point of a path or patterns in every tile, to freeze or crash the panel's tab; or nests to recurse the parser | Declared entities refuse it, as does an encoding other than UTF-8. Markers and patterns aren't kept, nor what names them. It may hold 10,000 elements, nest 64 deep, and draw 4,000 once each reference stands for what it names, each time it's named: a `<use>`, and a mask, clip path, filter or paint named by `url(#id)` in an attribute or a style attribute; anything that names itself, through others, refuses it. A style sheet may name a gradient by `url()`, and nothing else, as what its selectors reach can't be counted. The most any of the stores' logos draws so is 1,110; the heaviest image allowed draws twelve times at 48 px in under 40 ms in Chromium. |
| A name in the folder media reaches out of it | Only names of lowercase words and one extension are read or kept, through `os.Root`; a folder deeper than `media` is never read. A request's path parts are each checked against a pattern before anything is opened, and an image is opened through `os.Root` from the commit kept for a source applied. |
| Images fill the disk or the fetch | The folder media is read within limits of its own: 1,000 images, 1 MiB each, 32 MiB together, counted before a byte of one is kept, inside the 64 MiB pack. Over them, the commit is refused. A commit's images are kept beside its entries and go with them. |
| A stranger learns which sources an install reads by asking for their images | An image is served only to a signed-in person who may read the catalog, as an image request carries the session's cookie. |
| A source's entry names the images Dockwell ships for its own apps, to pass for one | Still refused: a `/catalog-media/` path in a source's entry is dropped, and the plan says so. A source's own images are its own, beside the name of the catalog it comes from. |
| A source that follows a branch makes the control plane ask a host over and over | Every source is looked at once an hour, give or take six minutes, and first within five minutes of a start; after a look that failed, the next waits five minutes, then twice as long each time, up to six hours. A look lists the branches through the same guarded client, and a move fetches one commit as a person's plan does, one at a time, within the same bounds. |
| A pushed commit changes what runs | A move changes only what the catalog offers. An install whose entry has a newer release shows an upgrade, which a person plans and applies, as before. |
| A source that follows moves with no one seeing it | Each move is Dockwell's own change, on Activity, with the notes a person's plan has: what the commit adds, changes and leaves out, and each install that loses or regains its upgrades. It can be undone. |
| An undone move comes straight back | Dockwell keeps the commit it last moved each source to, and its hourly look never moves the source back to it: the source stays where the undo put it until the branch moves again. |
| A first boot offline, or an install with no way out, has no catalog | The binary holds a snapshot of Dockwell/catalog at a pinned commit, made from the repository by a make target and checked against it in CI. Dockwell's own source starts at that commit, read from the snapshot, with no network. |
| A source named `dockwell`, or one that names Dockwell/catalog, passes for Dockwell's own | Dockwell's own is the source that reads `https://github.com/Dockwell/catalog` at `entries`, whatever it's named, and nothing else. Its name decides nothing. |
| A broken commit, or one that refuses every entry, empties the catalog | A commit that can't be read, or whose entries all fail when the commit before had some, leaves the source where it is. The Sources page says why, and an alert does too. |
| A branch is force-pushed to an older or a stranger's commit | It's followed as any move is: the plan says which commit it is, as the branch's, and what it changes. Pinning the source to a commit stops following. |

### Another store's catalog, converted on the server

A source may be 1Panel's app store, Dokploy's templates or Coolify's (ADR 0078). The control plane then parses YAML, TOML and JSON a stranger wrote, and once a source follows a branch, it does so with nobody watching.

| Threat | Mitigation |
| --- | --- |
| A store's commit is far larger than a source reads, as 1Panel's is 152 MiB of archives and databases | It's fetched in two rounds: its folders first, with `filter blob:limit=1`, in a pack of 16 MiB at most, then only the files its adapter reads, by their objects' names: 5,000 at most, 1 MiB each, 32 MiB together, in a pack of 64 MiB at most. A walk lists 20,000 files and folders at most, 8 deep. Every object is checked against its name, as above. A host that can't filter is fetched whole, within 64 MiB. |
| A host that says it filters sends every file anyway | The first round's pack is held to 16 MiB, and refused past it. |
| A file nests thousands of levels deep, to recurse a parser out of its stack | Each file read of a store is 256 KiB at most, and nests 64 levels at most, counted from its brackets and its indentation before any parser reads it. A compact block sequence nests with neither, and YAML's own parser stops it at 10,000 levels. |
| YAML aliases of aliases stand for millions of nodes, or a large anchor named a thousand times stands for gigabytes in a few thousand nodes | Expanding a file's aliases makes 100,000 nodes at most, and writes out 256 KiB at most, counted as each value is copied. |
| Dokploy's variables that each name the next ten times stand for gigabytes in a template of a few hundred bytes | A value comes to 4 KiB at most, a template's values to 256 KiB, in 10,000 steps. Each adapter checks the time once an app, and fetching and converting each have a minute of their own. |
| A licence's first line of a megabyte, or a compose file just under the limit, rides in each of 2,000 entries, to fill memory and the disk | Each entry repeats a copyright line of 200 characters at most. A commit converts to 16 MiB at most, counted as it's converted, or it's refused. A left-out app's reason is kept as 500 characters at most. |
| A store's text ends a comment in a kept entry's header and starts a field there, such as first steps the plan shows as Dockwell's own | The header holds a store's text as one line, each control character and line or paragraph separator made a space; everything else goes through the YAML encoder. A tree entry whose name holds a control character or a separator refuses the commit. |
| An `image:` line that's no service's, such as a variable, names a registry on this server, and pinning it has the agent ask there over plain HTTP | Only each service's own image, as the file is parsed and an install reads it, is pinned. Its registry is checked again by name when the plan is made, and the agent reads a registry its Docker doesn't name at public addresses alone, over HTTPS, wherever its name resolves. |
| A registry answers with a digest that isn't one | A digest must be `sha256:` and 64 hex digits, in the registry client and again before it's pinned. |
| A store's repository disappears, and a newer converter can't convert the commit an install came from | What the older converter kept stays, and is read, until a new conversion succeeds. |
| Two apps come to one ID, and whichever sorts last wins, differently from run to run | The first by its folder is kept, every time, and the other is left out, naming it. |
| A fork dates a commit far in the future, so its releases outrank every later commit's | A commit dated after now counts from when it's converted. |
| A repository copies a store's layout to pass for the store | An entry says "From 1Panel's app store" only for the store's own repository, and otherwise names the repository and the layout. |
| A template asks Dockwell to generate a secret of a billion characters, which an install would allocate | A secret any entry generates is 256 characters at most, checked for every source's entries, Dockwell's own format's too. A template's helper that asks for more leaves its app out. |
| A store's app names an image on this server's registry, a private network's or a metadata address, so pinning it at a plan probes the network | It's left out when it's converted: an image's registry may not be one netguard refuses. |
| A store holds thousands of apps, to take the control plane's time | 2,000 at most, counted before the adapter lists them. Converting a commit takes a minute at most, checked between apps, one commit at a time, once per commit and converter. |
| A store's app runs a script on the server as it installs | Nothing a store holds is ever run. An app with scripts, a build or shipped files is left out, with the reason. |
| An entry hides an image from the check of lines, in a flow mapping or a quoted key | Each service's image, as an install reads the file, must be one the file names plainly on an `image:` line by a tag, or be pinned by digest. An image a store names with no tag is written as `latest`, what Docker pulls for it, so the line names the tag the plan pins (ADR 0085). |
| A tag is pushed again upstream, to change what an install runs | An install pins each image by digest when it's planned, through the agent of its server, and the plan shows it. An upgrade keeps the digest an install runs for an image whose tag didn't change, and a companion keeps every digest, so only a plan that moves a tag moves what runs. |
| A tag that moves by itself, such as `latest`, changes what an install runs, or never takes a fix | It's pinned at the plan as any tag is, so what runs is the build a person approved. A new build is offered as an update, read by the same HEAD of the tag (ADR 0079), and taking it is an upgrade of the install, planned, backed up first and shown with its new digest, as any upgrade is. Nothing moves it by itself unless the person turned on automatic updates of that kind (ADR 0080, ADR 0085). |
| Pinning at a plan asks registries too often | Only a plan asks, never a refresh: a HEAD each, which no registry counts as a pull, 20 images a call, two calls reaching registries at once on a server, and digests kept 10 minutes, shared with a form's reads. |
| A store says it's under one licence and isn't | The licence is read from the repository's own licence file and matched to four licences' texts; anything else is `NOASSERTION`, and the plan says Dockwell can't tell it. |
| A store's words reach a person as markup, or as an instruction | An entry's summary is the store's line, one line of 160 characters at most, shown as text. The converter writes no first steps. |
| A store's logo is named so it reads a file outside the app's folder, or a file that isn't one, such as `../../.git/config` or a script | A logo is a file the store's own convention names in its folder: a plain name, one level, with the extension of an image the control plane serves, and there in the commit's listing. It's read with the other files' checks, by its object's name, and must pass the image checks above. |
| A store's logos fill the fetch, the disk or the time a read has | Logos are read in a round of their own, only for apps that convert, within the limits of a catalog's images: 1,000 at most, 1 MiB each, 32 MiB together, and within the fetch's minute. One over its limit leaves its app without one; a round that fails leaves every app without one, and no app out. |
| A store's README carries markup, an image that tracks who reads it, or a link that runs | What's kept of a README is Markdown without its blocks of HTML, its tags and its images, outside code, which is kept as text; control characters go, within 32 KiB. The panel makes headings, paragraphs, lists, emphasis, code and links into elements, never into HTML, and opens a link only as an HTTPS address, in a new tab, with no referrer. It's shown under the store's name, as the store's words. |
| A store fills the catalog's list with its READMEs, so every view of the catalog moves megabytes | The catalog's list leaves each README out, and each translation's description and README; the app's page reads them. A README is 32 KiB at most, a summary 240 characters on one line in any language, and an entry speaks 8 languages at most, each named by a tag. |
| A store names its app as one of Dockwell's own, to be installed in its place | It's joined to that app only with the same ID, name and image repository, and then only as another choice: the card is listed from Dockwell's own first, the default is Dockwell's own, and choosing the store's shows where it comes from and that Dockwell doesn't test it. An install from it upgrades from that store alone. Anything less certain is left out as `taken`. |

## Not covered

- **A private repository,** with credentials as a secret, and a source on a private network, which an admin would name, as host access, come later.
- **What a source's entries say in words,** such as a summary, is shown as written. The panel shows it as text, never as markup.
- **A store's images aren't held back 14 days,** as Dockwell's own catalog's are: the store chose that version, and a tag rebuilt every few weeks would never be installable. The plan shows the digest it installs (ADR 0078).
- **What an image shows** is the source's to choose, as its words are. A WebP, PNG or JPEG that decodes, or an SVG image as svgclean writes it, is drawn by the browser's own decoder, whose flaws are the browser's to fix.
- **A store's screenshots on other hosts** aren't fetched. A store's screenshots are read only where it keeps them in its repository (ADR 0083).
