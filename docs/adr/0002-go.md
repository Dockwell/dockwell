# 0002. Go for the agent and the control plane

- Status: Accepted
- Date: 2026-11-03

## Context

The agent runs on every server, from a 1 GB VPS to a 1,000-server estate. Its targets are under 40 MB of memory at idle, and under 250 MB for the control plane and agent together on one server. It has to ship as signed static binaries for amd64 and arm64 on Debian, Ubuntu, the RHEL family and Alpine. The PRD asked for Go or Rust and recommended Go.

## Decision

Write both the agent and the control plane in Go, in one module (`github.com/dockwell/dockwell`), building a single `dockwell` binary (see [0007](0007-one-binary-two-roles.md)).

## Consequences

- The libraries Dockwell builds on are Go: the Docker Engine client, `compose-go`, BuildKit, Railpack, Caddy, `wireguard-go` and `wgctrl`. They can be used directly, with no shelling out and no bindings.
- Builds are fast and cross-compile with no extra tooling. The contributor pool is large.
- No cgo, so every dependency has to be pure Go. That includes the SQLite driver ([0004](0004-sqlite-then-postgres.md)).
- Go's garbage collector makes memory budgets something to measure, not assume. Idle memory for the agent and the control plane is checked in CI from the first milestone, with `GOMEMLIMIT` set in the systemd units.
